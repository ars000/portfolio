# Портфолио

Одностраничный сайт. Исходники лежат в `static/`, на GitHub Pages уезжает собранная папка `dist/`.

Сайт: https://ars000.github.io/portfolio

## Первый запуск

Нужны Node.js (22+) и npm.

```bash
npm install
```

## Команды

| Команда | Когда использовать |
|---|---|
| `npm run dev` | Локальная разработка. Открывает http://localhost:4173, сам пересобирает SCSS и JS. |
| `npm run build` | Собрать продакшен в `dist/`. Саму папку в git не коммитить. |
| `npm run preview` | Проверить собранный `dist/` локально, как он будет на GitHub. |
| `npm run deploy` | Собрать проект и опубликовать `dist/` на ветку `gh-pages`. |

Править файлы только в `static/` (`index.html`, `scss/`, `js/`, картинки). Папка `dist/` появляется после сборки и может быть удалена — её всегда можно получить заново через `npm run build`.

## Как правильно деплоить на GitHub

1. Изменения закоммитить в основную ветку (`main` / `master`) и при необходимости запушить:

   ```bash
   git add .
   git commit -m "Описание изменений"
   git push
   ```

   Это сохраняет исходники. Сайт на GitHub Pages от этого **ещё не обновится**.

2. Опубликовать собранный сайт:

   ```bash
   npm run deploy
   ```

   Команда делает `vite build`, затем `gh-pages -d dist`: содержимое `dist/` попадает в ветку `gh-pages`.

3. Подождать 1–2 минуты и проверить https://ars000.github.io/portfolio

Первый раз `gh-pages` может запросить доступ к GitHub. Нужен push в этот репозиторий.

### Настройки GitHub Pages

В репозитории: **Settings → Pages**.

- Source: **Deploy from a branch**
- Branch: **`gh-pages`**, папка **`/ (root)`**

Менять это не нужно, если Pages уже был настроен под `gh-pages`.

### Чего не делать

- Не заливать на Pages папку `static/` — там исходники без бандла, сайт не заведётся.
- Не коммитить `dist/` и `node_modules/` (они в `.gitignore`).
- Не копировать файлы на `gh-pages` вручную: следующий `npm run deploy` всё равно перезапишет ветку.

Обычный цикл: правите в `static/` → смотрите через `npm run dev` → коммит исходников → `npm run deploy`.
